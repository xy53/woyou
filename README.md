# 卧游 (Woyou)

> 澄怀观道，卧以游之。——宗炳

**真实城市的文字旅行模拟。** 选一个国家、一座城市，旅行者用文字命令在真实的
街巷里旅行：看时段与天气流转的风景、和本地人聊出压箱底的故事、吃真实的地方菜、
找到地图上没有的深巷去处——最后带回一本自动写成的游记。

交互模式借鉴 [fox-river-valley](https://github.com/eckkk/fox-river-valley)：
**盲玩、旁观**。每条命令返回叙事文本 + 一行 `STATE {...}`，旅行者只凭输出决策。

```
〉 look
夕阳把河面烧成一条金红的带子，东山的棱线变成深蓝色的剪影。堤上的人
不知不觉都停了手里的事，朝着同一个方向坐着。

✦ 心愿达成：「在鸭川边看一次黄昏」

STATE {"day":2,"days":5,"t":7,"slot":"黄昏","city":"京都","loc":"鸭川河岸",...}
```

## 三分钟上手（零依赖，只需 uv 或 Python 3.10+）

```bash
# 离线示范：京都（手写内容包，不需要任何 API）
uv run play.py demo --mate aman --repl     # 带上吃货发小阿满，交互游玩

# 盲玩（单发命令接口，进度自动保存）
uv run play.py cmd look
uv run play.py cmd 去锦市场

# 浏览器观战页（旅行手帐风，实时刷新）
uv run play.py watch
```

## 全程零 API

游玩这一步完全离线——`demo` 的京都是手写内容包，任何 `new --city` 打开的城市也是
建城时就写死进缓存的内容包，引擎只读本地文件，不联网、不需要任何 API key。
`DEEPSEEK_API_KEY` **只有想当"建城人"的开发者、往内容库里加新城市时才需要**，
旅行者本身不用配置任何东西。

## 用 DeepSeek 建一座新城（开发者向）

1. 复制 `.env.example` 为 `.env`，填入你的 `DEEPSEEK_API_KEY`
2. 然后：

```bash
uv run play.py build --city 泉州        # 预先建城（调研+生成，约1-3分钟）
uv run play.py new --city 泉州 --days 5 --mate yanqiu
```

旅途中 `fly 奈良` 可以跨城——前提是已经用 `build` 生成过该城市的内容包。

**「真正的调研」是怎么做的：** 每座城生成时先跑一个**调研阶段**，DeepSeek 以研究者
身份产出一份事实性调研报告（`content/<城市>/research.md`：真实地名与当地写法、
历史掌故、物价量级、节令天气、本地人原型），再由第二阶段把报告转译成结构化内容包
（`pack.json`）。生成一次永久缓存，之后游玩零 token。可选 `WOYOU_WEB=1` 会在调研时
尝试抓取维基导游/维基百科作参考（部分网络环境不可用，失败自动跳过）。

一座城的生成成本：约 9-11 次调用、4-6 万 token，以 deepseek-chat 计不到一元人民币。
DeepSeek 只在建城时当写手，写完就退场——**建城之后，游玩全程零 API**，包括旅程
结束时的结算：引擎只读建城时写死的缓存，一步都不联网。

## 玩法设计

- **目标不是生存，是「回味值」**：随身只有钱、体力、时刻三样身体性的数字——
  没有心情条，也没有过程分数；日记按 风景/风味/人物/故事/意外/纪念/心愿 七类
  收集回忆，回味值只在终局出现一次，纯由日记的丰富度算出，给一句评语
  （走马观花 → 一期一会）
- **一天 10 刻**（清晨/上午/午后/黄昏/夜晚各 2 刻），行动耗时刻/体力/真实货币；
  同一地点在不同时段、不同天气是不同的文字
- **没有 `ask`/`do`，只有接得住的动词**：旅游是体验，不是查询——`listen`
  闭眼听、`wander` 漫无目的走、`join` 照本地人的样子做一次、`postcard`
  寄一张明信片……有限但每次都接得住的命令，比无限却常常落空的自由更自由；
  想说点什么，`note` 一句自语就够
- **心愿清单**：开局摆出这座城的十几条心愿选项（「在雨里走一段京都的路」），
  **自己挑**几条抄进手帐（`wish 1 3 5`），一条不挑也行；达成加分、绝不强制
- **深巷与故事**：2-4 个隐藏地点要靠本地人指点；NPC 聊到第 2-3 轮才讲压箱底的
  真实掌故（清水舞台的跳台史、茶泡饭的送客暗语……）
- **世界记得你（招牌机制）**：同一地点、同一时辰跨天重访会被认出——习惯正在
  形成；本地人认人，隔天再遇会「又是你」，还记得你买过什么；把一个地方逛尽，
  会收到「熟地」的完成感文字，地图上标一个「熟」字
- **旅游搭子（可选，零加成）**：阿满（吃货发小）/ 砚秋（历史控学长）/ 小柒（摄影系妹妹）
  不提供任何数值加成——他们是同行的人：自己在吃、在看，忍不住分享做过的功课，
  多数时候只是安静地在；每城另有 3-4 个写死的「搭子时刻」小剧场；独行也完全成立
- **自由续程**：随时 `fly <城市>` 跨城继续，跨国自动按汇率换钱（收点手续费），
  日记与预算连续，最后导出一篇多城游记
- **中途跳车**：任何时候 `end trip` 提前回程，照常结算（终局在命令行里直接打印
  「旅程结算」——不生成任何报告文件）
- **数值永远由引擎确定性结算**（种子化随机，同种子同旅程），文案全部在建城时
  写死进内容包，游玩时不做实时生成——模拟诚实、可复盘、可离线
- **`note` 自语**：旅行者可以（但从不必须）留一句随想，内嵌在时间线和游记里
  （"你说：「...」"）；零消耗、不计分
- **`share` 手帐**：旅程结束后，可用 `share` 生成一份自给自足的 HTML 手帐分享页，
  含封面、每日页、心愿、显影色卡；末尾可留一句话给朋友（"给你的话："手写体），
  也可以不留
- **显影：一趟旅行一种颜色**：终局的「旅程结算」不摆分数——走过的路、聊过的人、
  拍下的景各是一味染料，混成这趟旅行独有的色名与一句色话（「檀色——旧木头被手
  摸久了的颜色」）；也可随时 `uv run play.py report` 在命令行重新看一遍这份结算

## 项目结构

```
play.py            CLI：demo/new/build/cmd/export/report/watch/trips/packs
woyou/
  engine.py        游戏引擎（命令、结算、心愿、事件、世界记忆、搭子、跨城）
  state.py         旅程存档（多城市容器）
  content.py       内容包加载与校验
  generate.py      DeepSeek 生成管线（调研→骨架→细写→人物→杂项→搭子）
  research.py      调研阶段（可选网络参考）
  journal.py       日记与游记导出（原始条目版）
  report.py        旅程结算（终局文字：足迹/照片/故事/心愿/显影，纯离线、只说美好的事）
  share.py         手帐分享页（自给自足 HTML，含封面/日页/显影，可选留言）
  score.py         回味值与显影的染料表
  llm.py           DeepSeek 客户端（纯标准库）
content/
  companions.json  旅游搭子名册（全局）
  kyoto/           手写京都示范包（离线可玩，也是生成质量标杆）
web/observer.html  浏览器观战页
saves/             旅程存档与导出的游记（运行时生成）
PLAYER_GUIDE.md    旅行者指南（含可粘贴的系统提示词）
CITY_GUIDE.md      新增城市规范（调研→生成→校验→入库全流程）
```

## 两种玩法

1. **命令行盲玩**（推荐）：把 [PLAYER_GUIDE.md](PLAYER_GUIDE.md) 末尾的系统提示词
   交给任意能执行命令的 agent（Claude Code 等），旅行者会逐回合游玩——
   如果你想旁观，可以打开观战页，或者等旅程结束后看手帐。
2. **Python 接口**：`from woyou import new_trip, cmd`，在任何 agent 框架里循环调用。

旅程结束时（`end trip` 或睡满最后一晚）会自动在命令行打印一份「旅程结算」：
足迹、照片、故事、心愿、显影出的颜色，全离线生成、不落任何文件；想再看一遍，
随时 `uv run play.py report`。游记想导出成文件的话用 `uv run play.py export`
（日记的原始条目版）。旅行者还可以在游戏内输入 `share` 生成一份手帐风格的 HTML
分享页。
